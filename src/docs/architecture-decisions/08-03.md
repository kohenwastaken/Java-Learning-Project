# Architecture Decision — Transaction Türünü String Saklamak ve Hesap Geçmişini İki Alan Üzerinden Sorgulamak

- **Tarih:** 08-03
- **Durum:** Kabul edildi

## Bağlam

Transaction kayıtları üç işlem türünden birini taşır:

```text
DEPOSIT
WITHDRAWAL
TRANSFER
```

Ayrıca bir hesap işlem içinde kaynak veya hedef olarak bulunabilir.

Bir hesabın tam işlem geçmişinin görüntülenmesi için her iki rolün de sorgulanması gerekir.

## Karar

`TransactionType` enum değeri JPA tarafından string olarak saklanacaktır:

```java
@Enumerated(EnumType.STRING)
```

Bir hesaba ait işlem geçmişi şu iki entity alanı üzerinden aranacaktır:

```text
sourceAccountId
targetAccountId
```

Spring Data sorgu methodu:

```java
findBySourceAccountIdOrTargetAccountIdOrderByTransactionIdAsc(...)
```

olarak tanımlanacaktır.

Sonuçlar işlem ID’sine göre artan sırada döndürülecektir.

## Gerekçe

- Enum değerlerinin veritabanında okunabilir olması
- Enum sırası değiştiğinde eski kayıtların anlamının bozulmaması
- Gönderilen ve alınan transferlerin aynı işlem geçmişinde gösterilmesi
- Para yatırma ve çekme işlemlerinin kaynak hesap üzerinden bulunması
- Sonuç sırasının veritabanının varsayılan davranışına bırakılmaması

## Sonuçlar

### Olumlu

- İşlem türleri veritabanında açıkça okunabilir.
- Hesabın hem kaynak hem hedef olduğu işlemler bulunabilir.
- İşlem geçmişi tutarlı biçimde eski kayıttan yeni kayda sıralanır.
- Elle `@Query` yazmadan Spring Data method-name sorgusu kullanılabilir.

### Maliyet

- Repository method adı uzundur.
- Aynı hesap ID’sinin iki parametreye verilmesi gerekir.
- Daha karmaşık filtreler gerektiğinde özel JPQL veya SQL sorgusu gerekebilir.
