# Architecture Decision — Spring Data JPA'yı Adapter Arkasında Tutmak

## Bağlam

Application katmanında `CustomerRepository` ve `AccountRepository` portları bulunmaktadır. Spring Data JPA ise kendi repository interface'lerini ve JPA entity türlerini kullanır.

BankService'in doğrudan `JpaRepository` veya JPA entity sınıflarına bağımlı olması istenmemektedir.

## Karar

Spring Data repository'leri yalnızca persistence adapter katmanında kullanılacaktır.

```text
BankService
    ↓
Application repository portu
    ↓
PostgreSQL repository adapterı
    ↓
Spring Data repository
    ↓
PostgreSQL
```

Adapterlar domain modeli ile JPA entity modeli arasında dönüşüm yapacaktır.

## Gerekçe

- BankService'i Spring Data JPA'dan bağımsız tutmak
- Mevcut output portlarını korumak
- InMemory ve PostgreSQL implementasyonlarını değiştirilebilir kılmak
- Persistence ayrıntılarını adapter katmanında sınırlandırmak

## Sonuçlar

### Olumlu

- BankService yalnızca kendi repository interface'lerini tanır.
- InMemory ve PostgreSQL adapterları aynı portu uygulayabilir.
- Persistence teknolojisi değişse bile iş mantığı korunabilir.

### Maliyet

- Her repository için ek adapter sınıfı gerekir.
- `toEntity` ve `toDomain` dönüşümleri yazılmalıdır.
