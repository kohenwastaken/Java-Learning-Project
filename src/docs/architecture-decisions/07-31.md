# Architecture Decision — Para Değerlerini BigDecimal ile Saklamak

## Bağlam

`Account` bakiyesi finansal bir değerdir. `double` ve `float` türleri bazı ondalık değerleri tam temsil edemediği için yuvarlama hatalarına yol açabilir.

## Karar

Domain ve persistence modellerinde para değerleri `BigDecimal` olarak tutulacaktır.

`AccountJpaEntity.balance` alanı:

```java
@Column(
        nullable = false,
        precision = 19,
        scale = 2
)
private BigDecimal balance;
```

şeklinde eşlenecektir.

PostgreSQL tarafında yaklaşık karşılık:

```text
NUMERIC(19, 2)
```

## Gerekçe

- Finansal hesaplamalarda kayan nokta hatalarından kaçınmak
- Bakiye değerlerini kontrollü ondalık hassasiyetle saklamak
- Domain ve persistence katmanlarında tür uyumunu korumak

## Sonuçlar

### Olumlu

- Para değerleri güvenilir biçimde temsil edilir.
- Toplam ve ondalık basamak sayısı açıkça tanımlanır.

### Maliyet

- Karşılaştırmalarda `compareTo(...)` kullanılmalıdır.
- Daha farklı para birimleri için ölçek kuralları ayrıca ele alınabilir.
