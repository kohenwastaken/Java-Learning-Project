# Architecture Decision — PostgreSQL Bağlantısını Persistence Geçişinden Ayırmak

## Bağlam

Spring Boot uygulamasının PostgreSQL’e taşınmasında iki farklı konu bulunmaktadır:

1. Uygulamanın PostgreSQL sunucusuna bağlantı kurması
2. Mevcut repository implementasyonlarının PostgreSQL kullanacak şekilde değiştirilmesi

Bu iki değişikliğin aynı anda yapılması, bağlantı sorunlarıyla persistence tasarım sorunlarının birbirine karışmasına neden olabilir.

Ayrıca uygulama şifresinin kaynak kodda veya Git geçmişinde tutulmaması gerekmektedir.

## Karar

PostgreSQL geçişi aşamalı yapılacaktır.

İlk aşamada yalnızca şu parçalar tamamlanacaktır:

```text
JPA dependency
PostgreSQL JDBC driver
Datasource configuration
Environment variable ile şifre
Bağlantı doğrulaması
```

Mevcut `InMemory` repository’ler bu aşamada korunacaktır.

Bağlantı ayarları:

```properties
spring.datasource.url=jdbc:postgresql://localhost:5432/bank_db
spring.datasource.username=bank_user
spring.datasource.password=${BANK_DB_PASSWORD}
spring.jpa.hibernate.ddl-auto=none
```

Gerçek şifre repository’ye yazılmayacak, `BANK_DB_PASSWORD` environment variable’ından alınacaktır.

Hibernate’in şema üzerinde otomatik değişiklik yapması bağlantı testi aşamasında kapalı tutulacaktır.

## Gerekçe

- Bağlantı hatalarıyla entity ve repository hatalarını birbirinden ayırmak
- Küçük ve doğrulanabilir adımlarla ilerlemek
- Mevcut çalışan REST API davranışını bozmamak
- Şifrenin GitHub’a gönderilmesini önlemek
- Hibernate’in henüz tasarlanmamış tabloları otomatik oluşturmasını engellemek
- Hexagonal mimari sınırlarını koruyarak persistence adapterlarını daha sonra eklemek

## Sonuçlar

### Olumlu

- Spring Boot’un PostgreSQL’e bağlanabildiği bağımsız olarak doğrulanmıştır.
- Mevcut REST endpoint’leri ve `InMemory` repository’ler çalışmaya devam etmektedir.
- Veritabanı şifresi kaynak koddan ayrılmıştır.
- Entity ve adapter çalışmaları için temiz bir başlangıç noktası oluşmuştur.
- PostgreSQL geçişi customer, account ve transaction şeklinde küçük dikey dilimlere ayrılabilir.

### Maliyet

- PostgreSQL bağlantısı kurulmuş olsa da henüz kalıcı veri yazılmamaktadır.
- Uygulama her başlatıldığında environment variable’ın erişilebilir olması gerekir.
- Domain modeli ile JPA entity modeli arasında dönüşüm katmanı gerekecektir.
- Gelecekte şema yönetimi veya migration aracı için yeni karar verilmesi gerekecektir.

## Sonraki Adım

İlk persistence dikey dilimi müşteri kaydı olacaktır:

```text
Customer
→ CustomerJpaEntity
→ Spring Data repository
→ PostgreSQL adapter
→ customers tablosu
```

Bu tamamlandıktan sonra account ve transaction persistence katmanları eklenecektir.
