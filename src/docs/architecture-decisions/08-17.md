# Architecture Decision — Spring Boot ve PostgreSQL’i Docker Compose ile Ayrı Containerlarda Çalıştırmak

- **Tarih:** 08-17
- **Durum:** Kabul edildi

## Bağlam

Uygulamanın host bilgisayarda Java ve PostgreSQL kurulumuna bağlı kalmadan daha tekrar üretilebilir bir ortamda çalışması istendi.

Görev kapsamında Docker yapısının kurulması ve projenin tek yapı olarak çalıştırılabilmesi hedeflendi.

## Karar

Spring Boot uygulaması ve PostgreSQL ayrı Docker containerları olarak çalıştırılacaktır.

```text
bank-app container
+
postgres container
```

Docker Compose tarafından birlikte yönetilecektir.

Uygulama containerı Java 25 runtime kullanacaktır.

PostgreSQL verisi named volume içinde tutulacaktır.

## Container İletişimi

Containerlar Compose default network üzerinden haberleşir.

Datasource URL:

```text
jdbc:postgresql://postgres:5432/bank_db
```

şeklindedir.

Host’tan gelen HTTP trafiği:

```text
localhost:8080
↓
bank-app:8080
```

port mapping’i üzerinden uygulamaya ulaşır.

## Startup Order

PostgreSQL servisine healthcheck eklenmiştir.

`bank-app`, PostgreSQL healthy duruma gelmeden başlamaz.

## Persistence

Database dosyaları:

```text
bank_postgres_data
```

named volume’ünde tutulur.

Containerlar kaldırılıp yeniden oluşturulsa bile volume silinmediği sürece veriler korunur.

## Environment Configuration

Gerçek database password Compose dosyasına sabit yazılmaz.

Local `.env` dosyası Git tarafından ignore edilir.

`.env.example`, gerekli environment variable’ı güvenli bir örnekle gösterir.

## Sonuçlar

### Olumlu

- Uygulama Java 25 ile standart runtime’da çalışır.
- PostgreSQL ayrı container olarak yönetilir.
- Spring Boot ve PostgreSQL tek Compose yapısıyla başlatılabilir.
- Containerlar service adı üzerinden haberleşir.
- Database verisi container lifecycle’ından bağımsızdır.
- Projenin başka bir bilgisayarda yeniden kurulması kolaylaşır.

### Dikkat Edilecek Noktalar

- Docker Engine/Desktop gerekir.
- `.env` local olarak hazırlanmalıdır.
- Named volume bilinçli olarak silinirse database verileri kaybolur.
- Production için secret management ve migration yaklaşımı ayrıca geliştirilebilir.
