# 07-24 — Veritabanı, PostgreSQL ve İlk Yerel Kurulum

## Günün Amacı

Bu çalışmada veritabanı kavramları sıfırdan ele alındı ve banka uygulaması için yerel PostgreSQL ortamı hazırlandı.

Ana hedef, mevcut `InMemory` yapı ile kalıcı veritabanı arasındaki farkı anlamaktı.

## Mevcut In-Memory Yapı

Uygulama verileri şu anda bellekte tutulmaktadır:

```text
InMemoryCustomerRepository
InMemoryAccountRepository
InMemoryTransactionRepository
```

Bu repository’lerde yaklaşık olarak şu yapılar kullanılır:

```java
Map<Integer, Customer>
Map<Integer, Account>
List<Transaction>
```

Bu yaklaşımda uygulama kapanınca RAM temizlenir ve veriler kaybolur. Test ve öğrenme için uygundur ancak kalıcı veri saklama ihtiyacını karşılamaz.

## Veritabanı Nedir?

Veritabanı, uygulamanın verilerini düzenli ve kalıcı biçimde saklayan yapıdır.

```text
Uygulama kapansa bile müşteriler korunur
Bilgisayar yeniden başlasa bile bakiyeler kaybolmaz
İşlem geçmişi daha sonra tekrar okunabilir
```

Veritabanı yalnızca bir metin dosyası değildir. Veri bütünlüğünü, ilişkileri, aramayı, eşzamanlı işlemleri ve yetkilendirmeyi yönetir.

## PostgreSQL, SQL ve Veritabanı Ayrımı

```text
Veritabanı  → Saklanan veri yapısı
PostgreSQL  → Veritabanlarını yöneten yazılım
SQL         → PostgreSQL’e komut vermek için kullanılan dil
```

PostgreSQL içinde birden fazla veritabanı bulunabilir:

```text
PostgreSQL Server
├── postgres
├── bank_db
└── başka veritabanları
```

SQL ayrıca indirilen bir program değildir. PostgreSQL kurulduğunda SQL komutlarını çalıştırma desteği de gelir.

## İlişkisel Veritabanı Kavramları

İlişkisel veritabanlarında veriler tablolar hâlinde saklanır.

| id | name | surname |
|---:|---|---|
| 1 | Ahmet | Yılmaz |
| 2 | Ayşe | Demir |

```text
Tablo  → Aynı türdeki kayıtların bütünü
Satır  → Tek bir kayıt
Sütun  → Kaydın bir özelliği
```

Java tarafıyla yaklaşık karşılığı:

```text
Customer sınıfı  → customers tablosu
Customer nesnesi → tablodaki bir satır
name alanı       → name sütunu
```

### Primary Key

Bir tablodaki satırı benzersiz biçimde tanımlar.

```text
customers.id
```

### Foreign Key

Başka bir tablodaki kayda işaret eder.

```text
accounts.customer_id → customers.id
```

Bu ilişki, bir hesabın hangi müşteriye ait olduğunu belirtir.

## Temel SQL İşlemleri

```sql
SELECT * FROM customers;
```

```sql
INSERT INTO customers (name, surname)
VALUES ('Ahmet', 'Yılmaz');
```

```sql
UPDATE accounts
SET balance = 1500
WHERE id = 1;
```

```sql
DELETE FROM customers
WHERE id = 1;
```

Bu dört işlem CRUD olarak adlandırılır:

```text
Create
Read
Update
Delete
```

## PostgreSQL Kurulum Kararı

İlk olarak resmî macOS yükleyicisi ve pgAdmin denendi. pgAdmin arayüzü yerel makinede ağır çalıştığı için bu kurulum kaldırıldı ve Homebrew kurulumu tercih edildi.

```bash
brew install postgresql@18
brew services start postgresql@18
```

Homebrew kurulumu grafik uygulama oluşturmaz. PostgreSQL arka planda servis olarak çalışır ve `psql` ile yönetilir.

## `psql` Nedir?

`psql`, PostgreSQL sunucusuna terminalden bağlanmak için kullanılan istemcidir.

```bash
psql postgres
```

Başarılı bağlantıda:

```text
postgres=#
```

görülür. Çıkmak için:

```text
\q
```

kullanılır.

## Uygulamaya Özel Kullanıcı

Spring Boot uygulamasının PostgreSQL’e yönetici hesabıyla bağlanmaması için uygulamaya özel bir rol oluşturuldu:

```sql
CREATE ROLE bank_user WITH LOGIN;
```

Buradaki `bank_user`, banka uygulamasındaki müşteri değildir.

```text
bank_user → Spring Boot’un PostgreSQL’e bağlanacağı teknik kullanıcı
Customer  → Banka uygulamasına kaydolan domain kullanıcısı
```

Şifre şu komutla belirlendi:

```text
\password bank_user
```

Bu, SQL komutu değil `psql` meta-command’udur.

## `bank_db` Veritabanı

```sql
CREATE DATABASE bank_db OWNER bank_user;
```

Bu komut `bank_db` adlı veritabanını oluşturur ve sahibini `bank_user` yapar.

`bank_db`, Java projesi içinde oluşturulan bir class değildir:

```text
Java projesi → Veritabanına bağlanan kodları içerir
PostgreSQL   → Verileri saklayan ayrı çalışan sistemdir
bank_db      → PostgreSQL içindeki banka veritabanıdır
```

## Bağlantı Kontrolü

```bash
psql -h localhost -p 5432 -U bank_user -d bank_db
```

```text
-h localhost → PostgreSQL yerel bilgisayarda
-p 5432      → PostgreSQL portu
-U bank_user → Bağlanacak kullanıcı
-d bank_db   → Bağlanılacak veritabanı
```

Kontrol sorgusu:

```sql
SELECT current_database(), current_user;
```

Beklenen sonuç:

```text
current_database → bank_db
current_user     → bank_user
```

## Veritabanı Transaction Kavramı

Domain modelindeki `Transaction` sınıfı ile veritabanı transaction’ı aynı kavram değildir.

Transfer örneğinde:

```text
Göndericiden para çıkar
Alıcıya para ekle
İşlem kaydı oluştur
```

Beklenen davranış:

```text
Bütün adımlar başarılı → COMMIT
Bir adım başarısız      → ROLLBACK
```

Bu konu ileride Spring `@Transactional` kullanımıyla ele alınacaktır.

## Gün Sonu Durumu

```text
PostgreSQL 18 kuruldu

psql bağlantısı kuruldu
bank_user oluşturuldu

bank_db oluşturuldu
bank_user ile bank_db bağlantısı doğrulandı
```

Henüz tablo veya JPA entity oluşturulmadı.
