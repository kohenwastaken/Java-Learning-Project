# 08-04

## Günün Amacı

Bu çalışmada uygulamanın `TransactionRepository` portu ile Spring Data JPA repository’si arasında köprü kuran PostgreSQL adapterı oluşturuldu.

Oluşturulan sınıf:

```text
PostgreSqlTransactionRepositoryAdapter
```

Temel akış:

```text
Transaction
        ↕
TransactionJpaEntity
        ↓
TransactionSpringDataRepository
        ↓
PostgreSQL
```

---

## Adapterın Görevi

Application katmanındaki port:

```java
TransactionRepository
```

domain modeliyle çalışır:

```java
Transaction
```

Spring Data repository’si ise persistence modeliyle çalışır:

```java
TransactionJpaEntity
```

Adapter bu iki model arasında dönüşüm yapar ve repository çağrılarını Spring Data JPA’ya yönlendirir.

---

## Oluşturulan Adapter

Dosya:

```text
adapter/out/persistence/adapter/PostgreSqlTransactionRepositoryAdapter.java
```

Temel yapı:

```java
public class PostgreSqlTransactionRepositoryAdapter
        implements TransactionRepository {

    private final TransactionSpringDataRepository springDataRepository;

    public PostgreSqlTransactionRepositoryAdapter(
            TransactionSpringDataRepository springDataRepository
    ) {
        this.springDataRepository = springDataRepository;
    }
}
```

---

## `implements TransactionRepository`

```java
implements TransactionRepository
```

adapterın uygulamanın repository sözleşmesini yerine getirdiğini belirtir.

Bu nedenle şu methodlar uygulandı:

```java
Transaction save(Transaction transaction);

List<Transaction> findByAccountId(int accountId);
```

BankService yalnızca `TransactionRepository` portunu tanır. Arkada InMemory veya PostgreSQL adapterı kullanılmasını bilmek zorunda değildir.

---

## Constructor Injection

```java
private final TransactionSpringDataRepository springDataRepository;
```

alanı, adapterın kullanacağı Spring Data repository referansını tutar.

Constructor:

```java
public PostgreSqlTransactionRepositoryAdapter(
        TransactionSpringDataRepository springDataRepository
) {
    this.springDataRepository = springDataRepository;
}
```

ile dependency dışarıdan alınır ve sınıf alanına atanır.

Bu satır yeni repository implementation’ı üretmez. Spring Data tarafından oluşturulan repository nesnesinin adapter içinde kullanılmasını sağlar.

---

## `save()` Methodu

```java
@Override
public Transaction save(Transaction transaction) {
    TransactionJpaEntity entity = toEntity(transaction);

    TransactionJpaEntity savedEntity =
            springDataRepository.save(entity);

    return toDomain(savedEntity);
}
```

Adımlar:

```text
1. Domain Transaction alınır
2. TransactionJpaEntity'ye çevrilir
3. Spring Data save(...) çağrılır
4. Kaydedilen entity tekrar domain Transaction'a çevrilir
```

Tam akış:

```text
Transaction
   ↓ toEntity
TransactionJpaEntity
   ↓ save
PostgreSQL
   ↓
TransactionJpaEntity
   ↓ toDomain
Transaction
```

---

## `findByAccountId()` Methodu

```java
@Override
public List<Transaction> findByAccountId(int accountId) {
    return springDataRepository
            .findBySourceAccountIdOrTargetAccountIdOrderByTransactionIdAsc(
                    accountId,
                    accountId
            )
            .stream()
            .map(this::toDomain)
            .toList();
}
```

Application portu tek bir hesap ID’si alır:

```java
findByAccountId(int accountId)
```

Spring Data sorgusu ise iki farklı alanı kontrol eder:

```text
sourceAccountId
targetAccountId
```

Aynı hesap ID’si iki parametreye de gönderilir.

Örneğin:

```text
accountId = 2
```

için sorgunun anlamı:

```text
source_account_id = 2
veya
target_account_id = 2
```

olur.

Böylece hesap için şu işlemler birlikte bulunabilir:

```text
Para yatırmaları
Para çekmeleri
Gönderdiği transferler
Aldığı transferler
```

## Liste Dönüşümünde Stream Kullanımı

Spring Data repository şu türde liste döndürür:

```java
List<TransactionJpaEntity>
```

Application portunun beklediği tür:

```java
List<Transaction>
```

Bu nedenle listedeki her entity domain nesnesine dönüştürülür:

```java
.stream()
.map(this::toDomain)
.toList();
```

Anlamı:

```text
Listeyi akış hâline getir
→ Her TransactionJpaEntity için toDomain çalıştır
→ Yeni List<Transaction> oluştur
```

Geleneksel döngüyle yaklaşık karşılığı:

```java
List<Transaction> result = new ArrayList<>();

for (TransactionJpaEntity entity : entities) {
    result.add(toDomain(entity));
}

return result;
```

---

## Method Reference

```java
.map(this::toDomain)
```

şu lambda ifadesinin kısa hâlidir:

```java
.map(entity -> toDomain(entity))
```

Her entity için aynı dönüşüm methodunun kullanılacağını belirtir.

---

## Domain’den Entity’ye Dönüşüm

```java
private TransactionJpaEntity toEntity(Transaction transaction) {
    return new TransactionJpaEntity(
            transaction.getTransactionId(),
            transaction.getType(),
            transaction.getAmount(),
            transaction.getSourceId(),
            transaction.getTargetId()
    );
}
```

Bu method domain modelindeki alanları persistence entity’sine aktarır.

---

## Entity’den Domain’e Dönüşüm

```java
private Transaction toDomain(TransactionJpaEntity entity) {
    return new Transaction(
            entity.getTransactionId(),
            entity.getType(),
            entity.getAmount(),
            entity.getSourceAccountId(),
            entity.getTargetAccountId()
    );
}
```

Bu method PostgreSQL’den okunan entity verisini tekrar uygulamanın domain modeline çevirir.

---

## Null Hedef Hesap Davranışı

Para yatırma veya para çekme işleminde:

```java
entity.getTargetAccountId()
```

`null` dönebilir.

Domain `Transaction` constructor’ındaki hedef alanı:

```java
Integer targetID
```

olduğu için `null` değer güvenli biçimde taşınabilir.

---

## Adaptera Neden `@Repository` Eklenmedi?

Mevcut Spring configuration hâlâ InMemory repository bean’lerini kullanmaktadır.

PostgreSQL adapterına doğrudan `@Repository` eklemek, aynı port için birden fazla bean adayının oluşmasına neden olabilir.

Bu nedenle adapter sınıfı hazırlandı ancak henüz Spring tarafından etkin kullanılan repository olarak bağlanmadı.
