# 08-10 — JPA Persistence Katmanı ve PostgreSQL Adapterları

## Günün Amacı

Hexagonal architecture yapısını bozmadan domain modellerinin PostgreSQL’de saklanabilmesi için persistence katmanı geliştirildi.

## Domain Model ile JPA Entity Ayrımı

Domain modelleri:

```text
Customer
Account
Transaction
```

uygulamanın iş kavramlarını temsil eder.

Persistence tarafında ise ayrı sınıflar oluşturuldu:

```text
CustomerJpaEntity
AccountJpaEntity
TransactionJpaEntity
```

Böylece domain katmanı `@Entity`, `@Table`, `JpaRepository` veya PostgreSQL gibi persistence detaylarını bilmek zorunda kalmadı.

## JPA Entity

Persistence classının tabloyla eşlenmesi için:

```java
@Entity
@Table(name = "customers")
```

kullanıldı.

Primary key:

```java
@Id
@Column(name = "account_id")
private Integer accountId;
```

ile belirtildi.

JPA entity’lerinde framework kullanımı için parametresiz constructor tutuldu:

```java
protected CustomerJpaEntity() {
}
```

## Spring Data JPA Repository

Her entity için Spring Data repository interface’i oluşturuldu.

Örnek:

```java
public interface CustomerSpringDataRepository
        extends JpaRepository<CustomerJpaEntity, Integer> {
}
```

`JpaRepository` üzerinden `save`, `findById`, `findAll`, `deleteById` gibi temel işlemler hazır olarak kullanılabilir.

## Hexagonal Repository Portu ile Spring Data Repository Farkı

Application katmanındaki:

```text
CustomerRepository
AccountRepository
TransactionRepository
```

interface’leri outbound portlardır ve domain modelleriyle çalışır.

Persistence tarafındaki Spring Data repository’leri ise JPA entity’leriyle çalışır.

Aradaki dönüşümü PostgreSQL adapterları yapar:

```text
BankService
↓
Repository Port
↓
PostgreSQL Adapter
↓
Spring Data Repository
↓
PostgreSQL
```

## Account Persistence

`AccountJpaEntity` ile hesap ID’si ve bakiye veritabanında saklanabilecek hâle getirildi.

Para değerleri için `BigDecimal` kullanılmaya devam edildi:

```java
@Column(
        nullable = false,
        precision = 19,
        scale = 2
)
private BigDecimal balance;
```

## Transaction Persistence

Transaction entity’sinde:

```text
transactionId
type
amount
sourceAccountId
targetAccountId
```

alanları tutuldu.

Transaction türünün okunabilir biçimde saklanması için:

```java
@Enumerated(EnumType.STRING)
```

kullanıldı.

Böylece veritabanında:

```text
DEPOSIT
WITHDRAWAL
TRANSFER
```

değerleri saklanabilir.

## Custom Spring Data Query

Bir hesabın hem gönderici hem alıcı olduğu transactionları bulmak için derived query oluşturuldu:

```java
findBySourceAccountIdOrTargetAccountIdOrderByTransactionIdAsc(
        Integer sourceAccountId,
        Integer targetAccountId
);
```

Adapter aynı account ID’yi iki parametreye de göndererek source veya target hesabın eşleştiği kayıtları getirir.

Dönen entity listesi:

```java
.stream()
.map(this::toDomain)
.toList();
```

ile domain Transaction listesine çevrilir.

## ID Üretiminde Fark Edilen Problem

Persistence katmanı hazırlanırken `BankService` içindeki:

```java
private int userId = 1;
private int transactionId = 1;
```

sayaçlarının kalıcı PostgreSQL kullanımıyla uyumlu olmadığı fark edildi.

Uygulama yeniden başladığında sayaçların tekrar `1` olması veritabanındaki mevcut primary key değerleriyle çakışabilir.

Bu nedenle ID üretiminin application service’ten çıkarılıp persistence tarafına taşınması gerektiği belirlendi.

## Gün Sonu Çıkarımı

Persistence katmanının temel parçaları hazırlanmış oldu:

```text
JPA Entity
+
Spring Data Repository
+
PostgreSQL Adapter
```

Domain modelleri JPA veya PostgreSQL’e bağımlı hâle getirilmeden kalıcı veri saklama altyapısı hazırlandı.
