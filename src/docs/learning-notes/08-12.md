# 08-12 — PostgreSQL Persistence’ın Aktifleştirilmesi

## Günün Amacı

Daha önce hazırlanan PostgreSQL persistence katmanını Spring Boot uygulamasında gerçekten aktif etmek ve uygulamanın InMemory repository’ler yerine PostgreSQL adapterlarıyla çalışmasını sağlamak.

## BankConfiguration ile Adapter Seçimi

Uygulama daha önce repository portlarını InMemory implementasyonlarına bağlıyordu:

```java
@Bean
public CustomerRepository customerRepository() {
    return new InMemoryCustomerRepository();
}
```

Bu nedenle PostgreSQL entity, Spring Data repository ve adapter sınıfları yazılmış olsa bile normal Spring Boot çalışmasında hâlâ RAM içindeki repository’ler kullanılıyordu.

`BankConfiguration` güncellenerek repository portları PostgreSQL adapterlarına bağlandı.

Örnek:

```java
@Bean
public CustomerRepository customerRepository(
        CustomerSpringDataRepository springDataRepository
) {
    return new PostgreSqlCustomerRepositoryAdapter(
            springDataRepository
    );
}
```

Aynı yapı `AccountRepository` ve `TransactionRepository` için de uygulandı.

## BankConfiguration’ın Rolü

`BankConfiguration`, hexagonal architecture’ın kendisi değildir. Ancak portların hangi adapterlarla çalışacağını belirleyen composition/wiring noktasıdır.

Önce:

```text
CustomerRepository
↓
InMemoryCustomerRepository
```

kullanılırken artık:

```text
CustomerRepository
↓
PostgreSqlCustomerRepositoryAdapter
```

kullanılmaktadır.

`BankService` değişmeden kalmıştır. Bu, application katmanının concrete persistence teknolojisini bilmeden çalışabildiğini gösterir.

## Adapter Pattern

PostgreSQL bağlantısında adapter pattern kullanıldı:

```text
BankService
↓
CustomerRepository
↓
PostgreSqlCustomerRepositoryAdapter
↓
CustomerSpringDataRepository
↓
PostgreSQL
```

## Hibernate Schema Oluşturma Ayarı

`application.properties` içindeki:

```properties
spring.jpa.hibernate.ddl-auto=none
```

değeri:

```properties
spring.jpa.hibernate.ddl-auto=update
```

olarak değiştirildi.

Datasource ayarları:

```properties
spring.datasource.url=jdbc:postgresql://localhost:5432/bank_db
spring.datasource.username=bank_user
spring.datasource.password=${BANK_DB_PASSWORD}

spring.jpa.hibernate.ddl-auto=update
```

şeklinde kullanıldı.

## Environment Variable ile Database Password

Database parolası kaynak koduna yazılmadı:

```properties
spring.datasource.password=${BANK_DB_PASSWORD}
```

Terminalde:

```bash
export BANK_DB_PASSWORD='...'
```

ile environment variable tanımlandı.

## Spring Boot ve PostgreSQL Bağlantısının Doğrulanması

Uygulama:

```bash
mvn spring-boot:run
```

ile başlatıldı.

Loglarda üç JPA repository interface’inin bulunduğu, Hikari bağlantı havuzunun başladığı, PostgreSQL 18.4’e bağlanıldığı, JPA EntityManagerFactory’nin oluşturulduğu ve Tomcat’in 8080 portunda başladığı görüldü.

## PostgreSQL Tablolarının Oluşması

`psql` üzerinden:

```sql
\dt
```

çalıştırıldı.

Oluşan tablolar:

```text
accounts
customers
transactions
```

olarak doğrulandı.

## Tablo Yapılarının İncelenmesi

`customers.account_id` ve `transactions.transaction_id` alanlarının:

```text
generated by default as identity
```

olarak oluştuğu görüldü.

`accounts.account_id` ise identity değildir; mevcut tasarım gereği Customer ID ile aynı ID kullanılmaktadır.

`accounts.balance` ve `transactions.amount` alanları:

```text
numeric(19,2)
```

olarak oluştu.

`transaction_type` alanı için `DEPOSIT`, `WITHDRAWAL` ve `TRANSFER` değerlerini kabul eden check constraint oluştu.

## Gün Sonu Çıkarımı

Persistence katmanı yalnızca kod olarak mevcut olmaktan çıkıp gerçek Spring Boot çalışma akışında kullanılmaya başlandı:

```text
REST Controller
↓
BankService
↓
Repository Port
↓
PostgreSQL Adapter
↓
Spring Data JPA
↓
PostgreSQL
```
