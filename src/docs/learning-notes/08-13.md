# 08-13 — Gerçek PostgreSQL Testleri, Restart Kontrolü ve Transaction Yönetimi

## Günün Amacı

PostgreSQL persistence katmanını gerçek API çağrılarıyla doğrulamak, uygulama restart sonrasında verilerin ve generated ID değerlerinin devam ettiğini kontrol etmek ve çok adımlı veritabanı işlemlerini transaction sınırları içine almak.

## Postman ile Gerçek PostgreSQL Testi

Postman üzerinden müşteri oluşturma, deposit, withdrawal ve transfer işlemleri yapıldı.

`customers`, `accounts` ve `transactions` tabloları `psql` üzerinden sorgulandı ve verilerin gerçekten PostgreSQL’e yazıldığı doğrulandı.

Örnek sorgular:

```sql
SELECT * FROM customers;
SELECT * FROM accounts;
SELECT * FROM transactions ORDER BY transaction_id;
```

Transaction tablosunda `DEPOSIT`, `WITHDRAWAL` ve `TRANSFER` kayıtları görüldü.

## Restart Sonrası Persistence

Uygulama yeniden başlatıldıktan sonra mevcut verilerin kaybolmadığı kontrol edildi.

Özellikle Customer ve Transaction generated ID değerlerinin tekrar `1`den başlamadığı, mevcut kayıtların devamından ilerlediği görüldü.

Bu sonuç, daha önce kaldırılan:

```java
private int userId = 1;
private int transactionId = 1;
```

application sayaçlarının artık gereksiz olduğunu ve ID üretiminin persistence katmanında doğru çalıştığını doğruladı.

## Neden `@Transactional` Eklendi?

Bazı banking operasyonları birden fazla database write içerir.

Transfer:

```text
Sender account update
↓
Receiver account update
↓
Transaction insert
```

Müşteri kaydı:

```text
Customer insert
↓
Account insert
```

Deposit ve withdrawal:

```text
Account update
↓
Transaction insert
```

Bu operasyonların ortasında hata oluşursa işlemin yarım kalmaması gerekir.

## Transactional Methodlar

Aşağıdaki methodlara:

```java
@Transactional
```

eklendi:

```text
registerCustomer
depositToAccount
withdrawFromAccount
transferFromAccount
```

Read operasyonlarına bu aşamada annotation eklenmedi.

## Atomicity

Beklenen davranış:

```text
Bütün write işlemleri başarılı
→ COMMIT
```

ve:

```text
İşlemlerden biri başarısız
→ ROLLBACK
```

şeklindedir.

Özellikle transfer gibi işlemlerde sender ve receiver bakiyelerinin birbirinden bağımsız şekilde kalıcılaşması kabul edilemez.

## Test Sonucu

`@Transactional` değişikliklerinden sonra:

```bash
mvn clean test
```

çalıştırıldı ve `BUILD SUCCESS` sonucu alındı.

Daha sonra Postman üzerinden gerçek transfer işlemi tekrar yapıldı ve PostgreSQL tarafında başarıyla kaydedildi.
