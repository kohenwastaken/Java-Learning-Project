# 08-03

## Günün Amacı

Bu çalışmada işlem kayıtlarının PostgreSQL tarafındaki persistence modeli oluşturuldu ve bir hesaba ait işlemleri bulmak için özel bir Spring Data JPA repository methodu tanımlandı.

Oluşturulan parçalar:

```text
TransactionJpaEntity
TransactionSpringDataRepository
```

## Mevcut Domain Modeli

Domain sınıfı:

```java
Transaction
```

şu alanlara sahiptir:

```text
transactionID
type
amount
sourceID
targetID
```

İşlem türleri domain içinde enum olarak tanımlıdır:

```java
public enum TransactionType {
    DEPOSIT,
    WITHDRAWAL,
    TRANSFER
}
```

## `TransactionJpaEntity`

Dosya:

```text
adapter/out/persistence/entity/TransactionJpaEntity.java
```

Temel yapı:

```java
@Entity
@Table(name = "transactions")
public class TransactionJpaEntity {

    @Id
    @Column(name = "transaction_id")
    private Integer transactionId;

    @Enumerated(EnumType.STRING)
    @Column(name = "transaction_type", nullable = false)
    private TransactionType type;

    @Column(
            nullable = false,
            precision = 19,
            scale = 2
    )
    private BigDecimal amount;

    @Column(name = "source_account_id", nullable = false)
    private Integer sourceAccountId;

    @Column(name = "target_account_id")
    private Integer targetAccountId;

    protected TransactionJpaEntity() {
    }
}
```

## Enum Değerlerinin Saklanması

Entity alanında:

```java
@Enumerated(EnumType.STRING)
private TransactionType type;
```

kullanıldı.

Bu sayede enum değerleri veritabanında okunabilir metinler olarak saklanacaktır:

```text
DEPOSIT
WITHDRAWAL
TRANSFER
```

Sayısal sıra değerleriyle saklama tercih edilmedi:

```text
0
1
2
```

String kullanımı, enum elemanlarının sırası daha sonra değişse bile eski kayıtların anlamının korunmasına yardımcı olur.

---

## `targetAccountId` Neden Nullable?

Para yatırma ve para çekme işlemlerinde hedef hesap yoktur:

```text
DEPOSIT    → target_account_id = null
WITHDRAWAL → target_account_id = null
```

Transfer işleminde hedef hesap vardır:

```text
TRANSFER → target_account_id = alıcı hesap
```

Bu nedenle alan:

```java
private Integer targetAccountId;
```

olarak tanımlandı ve `nullable = false` eklenmedi.

Primitive `int`, `null` taşıyamadığı için wrapper türü olan `Integer` kullanıldı.

## Kaynak Hesap Alanı

```java
@Column(name = "source_account_id", nullable = false)
private Integer sourceAccountId;
```

Her işlem bir kaynak hesaba bağlıdır:

```text
Para yatırma → işlemin yapıldığı hesap
Para çekme   → paranın çekildiği hesap
Transfer     → parayı gönderen hesap
```

Bu nedenle kaynak hesap alanı boş bırakılamaz.

## Para Tutarının Saklanması

## `TransactionSpringDataRepository`

Dosya:

```text
adapter/out/persistence/repository/TransactionSpringDataRepository.java
```

İçerik:

```java
public interface TransactionSpringDataRepository
        extends JpaRepository<TransactionJpaEntity, Integer> {

    List<TransactionJpaEntity>
    findBySourceAccountIdOrTargetAccountIdOrderByTransactionIdAsc(
            Integer sourceAccountId,
            Integer targetAccountId
    );
}
```

---

## Neden Özel Repository Methodu Gerekti?

Hazır `JpaRepository` methodları arasında:

```text
save
findById
findAll
deleteById
```

bulunur.

Ancak uygulamanın repository portunda şu özel ihtiyaç vardır:

```java
List<Transaction> findByAccountId(int accountId);
```

Bir hesap işlemde iki farklı rolde bulunabilir:

```text
sourceAccountId → işlemi yapan veya gönderen hesap
targetAccountId → transferi alan hesap
```

Bu nedenle sorgu iki alanı da kontrol etmelidir.

---

## Method Adının Okunması

```java
findBySourceAccountIdOrTargetAccountIdOrderByTransactionIdAsc
```

parçalara ayrıldığında:

```text
findBy
→ Kayıtları bul

SourceAccountId
→ sourceAccountId alanını kontrol et

Or
→ veya

TargetAccountId
→ targetAccountId alanını kontrol et

OrderByTransactionIdAsc
→ transactionId değerine göre artan sırala
```

Yaklaşık SQL karşılığı:

```sql
SELECT *
FROM transactions
WHERE source_account_id = ?
   OR target_account_id = ?
ORDER BY transaction_id ASC;
```

Spring Data JPA, entity alan adlarını ve method isminde kullanılan anahtar kelimeleri analiz ederek sorguyu oluşturur.

---

## Neden İki Parametre Kullanıldı?

Method iki ayrı entity alanını karşılaştırdığı için iki parametre alır:

```java
Integer sourceAccountId,
Integer targetAccountId
```

Adapter içinde aynı hesap ID’si iki kez gönderilecektir:

```java
repository
    .findBySourceAccountIdOrTargetAccountIdOrderByTransactionIdAsc(
        accountId,
        accountId
    );
```

Böylece sorgu şu anlama gelir:

```text
sourceAccountId = accountId
veya
targetAccountId = accountId
```

## Açık Sıralama Kararı

Veritabanı sorgularında sıralama belirtilmediğinde sonuç sırasına güvenilmemelidir.

Bu nedenle:

```text

```

eklenerek işlem geçmişinin eski kayıttan yeni kayda doğru dönmesi sağlandı.
