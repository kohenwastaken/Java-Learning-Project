# 07-30 — Customer PostgreSQL Repository Adapterı

## Günün Amacı

Bu çalışmada `CustomerRepository` portu ile `CustomerSpringDataRepository` arasında köprü kuran `PostgreSqlCustomerRepositoryAdapter` oluşturuldu.

## Neden Adapter Gerekiyor?

İki repository farklı model kullanır:

```text
CustomerRepository
→ Customer ile çalışır.

CustomerSpringDataRepository
→ CustomerJpaEntity ile çalışır.
```

Dolayısıyla domain ve persistence modelleri arasında dönüşüm gerekir.

## Adapterın Temel Yapısı

```java
public class PostgreSqlCustomerRepositoryAdapter
        implements CustomerRepository {

    private final CustomerSpringDataRepository springDataRepository;

    public PostgreSqlCustomerRepositoryAdapter(
            CustomerSpringDataRepository springDataRepository
    ) {
        this.springDataRepository = springDataRepository;
    }
}
```

## `implements CustomerRepository`

Adapterın uygulamanın repository sözleşmesine uyduğunu belirtir. Bu nedenle şu methodları sağlar:

```java
Customer save(Customer customer);
Optional<Customer> findById(int customerId);
```

BankService, InMemory repository ile PostgreSQL adapterı arasındaki farkı bilmez; yalnızca `CustomerRepository` interface'ini görür.

## `private final` Alan

```java
private final CustomerSpringDataRepository springDataRepository;
```

Bu satır yeni nesne oluşturmaz. Dışarıdan verilecek repository nesnesinin referansını saklayacak alan tanımlar.

```text
private → Yalnızca adapter erişir.
final   → Constructor'dan sonra başka repository ile değiştirilemez.
```

## Constructor Injection

```java
public PostgreSqlCustomerRepositoryAdapter(
        CustomerSpringDataRepository springDataRepository
) {
    this.springDataRepository = springDataRepository;
}
```

Dışarıdan gelen repository nesnesi adapterın alanında saklanır. Spring bağlantısı yapıldığında gerçek Spring Data proxy nesnesini constructor'a Spring verecektir.

## `save` Akışı

```java
@Override
public Customer save(Customer customer) {
    CustomerJpaEntity entity = toEntity(customer);

    CustomerJpaEntity savedEntity =
            springDataRepository.save(entity);

    return toDomain(savedEntity);
}
```

Akış:

```text
Customer
   ↓ toEntity
CustomerJpaEntity
   ↓ save
PostgreSQL
   ↓
CustomerJpaEntity
   ↓ toDomain
Customer
```

## `findById` Akışı

```java
@Override
public Optional<Customer> findById(int customerId) {
    return springDataRepository
            .findById(customerId)
            .map(this::toDomain);
}
```

Spring Data'nın dönüşü:

```java
Optional<CustomerJpaEntity>
```

Application portunun dönüşü:

```java
Optional<Customer>
```

`map(this::toDomain)` bulunduğu zaman entity'yi domain nesnesine çevirir; bulunmadığında `Optional.empty()` korunur.

## Dönüşüm Methodları

```java
private CustomerJpaEntity toEntity(Customer customer) {
    return new CustomerJpaEntity(
            customer.getAccId(),
            customer.getName(),
            customer.getSurname(),
            customer.getPassword()
    );
}
```

```java
private Customer toDomain(CustomerJpaEntity entity) {
    return new Customer(
            entity.getName(),
            entity.getSurname(),
            entity.getPassword(),
            entity.getAccountId()
    );
}
```

## `getPassword()` Eklenmesi

Entity oluşturulurken mevcut parola değerine ulaşmak gerektiği için domain `Customer` sınıfına:

```java
public String getPassword() {
    return password;
}
```

eklendi.

REST response'ları DTO üzerinden döndüğü için bu getter parolanın kendiliğinden API cevabına çıkmasına yol açmaz. Parola hashleme bu çalışmada ele alınmadı.

## Adaptera Neden `@Repository` Eklenmedi?

`BankConfiguration` hâlâ `InMemoryCustomerRepository` bean'ini oluşturmaktadır. PostgreSQL adapterı da aynı anda bean yapılsaydı aynı `CustomerRepository` portu için iki aday oluşabilirdi.

Bu nedenle adapter hazırlandı fakat henüz Spring bean olarak etkinleştirilmedi.
