# 07-28 — JPA Entity ve Persistence Modeli Temelleri

## Günün Amacı

Bu çalışmada domain modeli ile PostgreSQL'e karşılık gelen persistence modelinin neden ayrı tutulduğu öğrenildi. İlk persistence modeli olarak `CustomerJpaEntity` oluşturuldu.

## Domain Modeli ve Persistence Modeli

```text
Customer
→ Uygulamanın iş modelidir.
→ BankService tarafından kullanılır.
→ JPA ve PostgreSQL'i bilmez.

CustomerJpaEntity
→ Veritabanı modelidir.
→ customers tablosuna karşılık gelir.
→ JPA annotation'larını bilir.
```

Domain sınıfına doğrudan `@Entity` eklemek mümkün olsa da bu, domain katmanını JPA ve Hibernate'e bağımlı hâle getirirdi. Hexagonal mimariyi korumak için ayrı entity sınıfı tercih edildi.

## Oluşturulan Package

```text
src/main/java/org/example/bank/adapter/out/persistence/entity
```

## `CustomerJpaEntity`

```java
@Entity
@Table(name = "customers")
public class CustomerJpaEntity {

    @Id
    @Column(name = "account_id")
    private Integer accountId;

    @Column(nullable = false)
    private String name;

    @Column(nullable = false)
    private String surname;

    @Column(nullable = false)
    private String password;

    protected CustomerJpaEntity() {
    }

    public CustomerJpaEntity(
            Integer accountId,
            String name,
            String surname,
            String password
    ) {
        this.accountId = accountId;
        this.name = name;
        this.surname = surname;
        this.password = password;
    }
}
```

## Annotation'ların Görevleri

### `@Entity`

Sınıfın JPA tarafından yönetilen bir entity olduğunu belirtir.

### `@Table(name = "customers")`

Entity'yi PostgreSQL'deki `customers` tablosuyla eşleştirir.

### `@Id`

`accountId` alanının primary key olduğunu belirtir.

### `@Column`

```java
@Column(name = "account_id")
```

Java'daki `accountId` alanını veritabanındaki `account_id` sütununa bağlar.

```java
@Column(nullable = false)
```

ilgili sütunun `null` kabul etmemesini sağlar.

## Parametresiz Constructor

```java
protected CustomerJpaEntity() {
}
```

Hibernate, veritabanından kayıt okurken entity nesnesi oluşturabilmek için parametresiz constructor kullanır. `protected` seçimi Hibernate'in erişmesine izin verirken uygulama kodunda gereksiz boş entity oluşturulmasını sınırlar.

## Neden Alanlar `final` Değil?

JPA/Hibernate entity nesnesini oluşturup alanlarını doldurabildiği için persistent alanların `final` olmaması tercih edilir.

## `Integer` ve `int`

Domain modelinde `int`, entity'de `Integer` kullanıldı. `Integer`, gerektiğinde `null` değerini temsil edebilir ve ID üretiminin daha sonra PostgreSQL'e bırakılmasına uyum sağlayabilir.

## ID Üretimi

Mevcut `BankService` hâlâ ID üretmektedir:

```java
private int userId = 1;
```

Bu nedenle entity'ye henüz `@GeneratedValue` eklenmedi. Bu çalışma gününde ID üretim mantığı değiştirilmedi.

## Şema Yönetimi

Mevcut ayar:

```properties
spring.jpa.hibernate.ddl-auto=none
```

olduğu için entity sınıfı oluşturulmasına rağmen PostgreSQL'de tablo oluşturulmadı.
